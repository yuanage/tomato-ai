# 番茄AI · 全面优化方案（v1）

> 基线：回退后稳定形态 + Tauri 原生 APK（v0.1.1，arm64）· 33/33 测试 · 前端 gzip 128KB · 源码约 2600 行
> 约束继承：极简护眼、少动效、零重型框架、本地优先、包体积敏感。所有方案以此为前提。

---

## 优化域一：界面设计（UI/UX）

### 技术选型
- **设计令牌 v2**（零依赖）：在现有 `base.css` CSS 变量体系上扩展——完整字号阶梯（display/headline/title/body/label 5 级）、间距网格（4px 基准）、圆角/阴影/动效时长令牌。所有组件只允许引用令牌，禁止硬编码色值。
- **组件样式统一**：对 NaiveUI 组件继续走 `themeOverrides` 全局注入（现已有），补齐 Input/Select/Switch/Card/Modal 的圆角与配色令牌化。
- **响应式**：保留 480px 手机壳为主形态；新增 `@media (min-width: 768px)` 断点（平板/桌面双栏：内容区 + 侧边统计卡），渐进增强不破坏手机端。
- **暗色模式（可选项，需拍板）**：令牌体系已就绪，暗色仅需一组变量覆盖 + `prefers-color-scheme` 自动切换；工作量约 0.5 天。PRD 未要求，建议列为 P3 可选。

### 实施步骤
1. 盘点全部硬编码样式 → 迁移到令牌（纯 CSS 重构，无逻辑改动）；
2. 统一 5 个页面 + 底部导航的标题层级（现仅统计页有卡片标题规范）；
3. 空状态/加载态/错误态三态样式规范（各页面一套复用）；
4. 768px 断点双栏布局（仅统计页与 AI 页受益，其余页面保持单栏）。

### 验收标准
- `grep` 源码中 `#[0-9a-f]{3,6}` 硬编码色值数量较基线下降 ≥80%（仅令牌文件保留）；
- 5 页面视觉走查：标题层级、间距、圆角一致；
- 480px / 768px / 1280px 三档宽度无横向滚动、无布局断裂。

## 优化域二：功能联动增强

### 现状与差距
模块状态已通过单例共享（usePomodoro/useTasks/useSettings/useAiAgents/useStats），**数据层联动已通**；缺的是**操作层联动**：跨模块跳转、快捷入口、统一反馈。

### 实施步骤
1. **跨模块快捷动作**：
   - 任务页每行加"▶ 开始专注"按钮 → 跳转专注页并预选该任务（需恢复路线A的任务绑定，见依赖说明）；
   - 统计页柱状图点击某天 → 弹出当日番茄记录列表；
   - AI 拆解导入后 → Toast 附带"查看任务"快捷跳转。
2. **状态同步补强**：统计页在番茄完成事件时自动刷新（现仅 visibilitychange 触发，补全局事件总线 `usePomodoro.onComplete` 广播）。
3. **反馈统一**：所有成功/失败提示统一走 `useMessage`，文案模板化（操作名 + 结果），杜绝 alert。
4. **减少操作步骤**：专注页时长记忆上次选择（settings 增加 `lastDurationMinutes`）。

**依赖说明**：任务绑定功能在回退中移除，联动增强的"任务→专注"快捷动作依赖它；建议作为联动阶段的第一子任务从 git 检查点 `9f52d11` 摘取相关代码**单独恢复并观察**（48h 无回归再继续）。

### 验收标准
- 从任意模块到达目标功能 ≤2 次点击；
- 番茄完成后统计页 3 秒内自动反映（无需手动刷新）；
- 全局提示样式与文案格式一致（走查 10 个操作点）。

## 优化域三：数据可视化与微动效

### 技术选型（关键决策点）
| 方案 | 体积 | 能力 | 建议 |
|---|---|---|---|
| A. 手写 SVG 图表（折线/环形） | **0 依赖** | 近7天趋势线、完成率环，足够本项目 | ✅ **推荐**（符合 PRD 零依赖） |
| B. uPlot | ~40KB | 高性能多图 | 备选（若未来图表需求爆发） |
| C. ECharts | ~300KB+ | 全能 | ❌ 与包体积约束冲突，不采用 |

### 实施步骤
1. 近 7 天柱状图升级为**柱状 + 趋势折线**组合（手写 SVG，含 hover 数值提示）；
2. 任务完成率改为**环形进度**（复用 TimerRing 组件模式）；
3. 微动效（全部 ≤200ms、仅 transform/opacity，尊重 `prefers-reduced-motion`）：
   - 页面切换 150ms 淡入（Vue `<Transition>`）；
   - 底部导航切换图标缩放反馈；
   - 番茄完成时进度环一次脉冲 + 完成卡淡入；
4. 首屏加载：路由级骨架屏（骨架 div，非第三方库）。

### 验收标准
- 图表在 2000 条记录下渲染 <50ms；
- 动效开启 `prefers-reduced-motion` 时全部禁用；
- 前端 gzip 增量 ≤15KB；
- 中端真机（4GB RAM）滑动/切换无掉帧感知。

## 优化域四：本地 AI 能力（分层方案，重点说明）

**现实约束**：Tauri Android WebView 环境 WebGPU 支持不可靠（WebLLM 路线风险高）；APK 体积敏感，不可能内置大模型。因此采用**三层递进**，每层独立可用：

### Tier 1：本地规则引擎"离线洞察"（推荐立即做，1-2 天，零依赖）
- 纯 TypeScript 规则引擎，读取本地番茄/任务数据，**完全离线**生成：
  - 专注洞察：本周最佳专注时段、连续专注天数、放弃率预警；
  - 任务建议：基于预估番茄数超限的任务给"建议拆分"提示；
  - 每日一句话总结（模板 + 数据插值）。
- **技术实现**：`src/api/localInsights.js`（纯函数，可单测），AI 页新增"离线洞察"卡片区，与在线 Agent 并列；设置页可设"无网络时自动使用离线洞察"。
- 验收：飞行模式下洞察功能完整可用；规则全部有单测。

### Tier 2：端侧小模型（可选，3-5 天，真机验证后决策）
- **技术路线**：Rust 侧集成 `llama.cpp` 绑定（llama-cpp-2 crate，非 Agent 框架，符合 PRD）+ **Qwen2.5-0.5B-Instruct Q4 量化**（约 400MB，首用时按需下载到应用数据目录，不进 APK）。
- **性能预期**：4GB+ RAM 设备 CPU 推理 5~15 tokens/s；低于阈值自动回退 Tier 1。
- **交互接口**：与现有 `chatJSON` 同构的 `localChatJSON(system, user)`，AI 页加"本地模型/云端 API"切换开关；Agent Prompt 复用。
- **前置条件**：Tier 1 上线且真机验证；设备 RAM ≥4GB 检测守卫。

### Tier 3：云端 API（现状保留）
- 现有 OpenAI 兼容调用不动，作为最高质量档位。

### 验收标准（Tier 1）
- 飞行模式下三大洞察输出正确（对照手工计算）；
- 数据量 1000 条记录时计算 <10ms；
- 规则覆盖率：全部规则有单元测试。

## 分阶段实施计划

| 阶段 | 内容 | 工期 | 优先级 | 依赖 |
|---|---|---|---|---|
| 0 | 基线测量（包体/首屏/内存）+ 设计令牌 v2 | 0.5 天 | P0 | 无 |
| 1 | UI 令牌落地 + 三态规范 + 768px 断点 | 2~3 天 | P1 | 阶段0 |
| 2 | 功能联动（含任务绑定单独恢复观察） | 2 天 | P1 | 阶段0 |
| 3 | SVG 图表 + 微动效 + 骨架屏 | 2 天 | P2 | 阶段1 |
| 4 | 本地 AI Tier 1（离线洞察） | 1~2 天 | P1 | 无（可与阶段2并行） |
| 5 | 本地 AI Tier 2（端侧模型，可选） | 3~5 天 | P3 | 阶段4 + 真机资源验证 |
| 6 | 暗色模式（可选） | 0.5 天 | P3 | 阶段1 |

每阶段结束固定动作：`npm run test` + `npm run build` + 真机冒烟 + git 提交 + APK 版本号递增。

## 资源估算
- 人力：开发者 1 名（AI 助手，全栈）；用户投入：每阶段结束 15 分钟真机验收；
- 设备：现有 Win 机器（工具链已就绪）+ 安卓真机；
- 新增依赖：仅暗色模式/图表均零依赖；Tier 2 新增 llama-cpp-2 crate（Rust 侧，不影响前端包体）。

## 风险登记册
| 风险 | 概率 | 影响 | 预防 | 应急 |
|---|---|---|---|---|
| 任务绑定恢复引发回归（历史卡死诱因区） | 中 | 中 | 单独提交 + 48h 观察窗 | git 秒级回退 |
| 微动效在弱 WebView 掉帧 | 中 | 低 | 仅 CSS transform/opacity + reduced-motion | 一键全局关闭开关 |
| SVG 图表大数据卡顿 | 低 | 低 | 数据聚合后渲染（≤7/31 天粒度） | 降级回柱状图 |
| Tier 2 端侧模型推理过慢/OOM | 高 | 中 | RAM 检测守卫 + 按需下载 + 自动回退 Tier 1 | 功能开关下线 |
| UI 重构碰坏样式 | 中 | 中 | 纯 CSS 重构不改逻辑 + 每步测试 | git 检查点回退 |

## 进度跟踪与验收机制
1. 每阶段一个 git 检查点（提交信息带阶段号）；
2. 阶段验收 = 本文档对应"验收标准"逐条核对 + 真机冒烟；
3. 包体积警戒线：前端 gzip ≤145KB（现 128KB），超线即复盘；
4. 每阶段完成输出简报（完成项/偏差/下一阶段预告）。

## 需要拍板的决策点
1. 暗色模式做不做（建议 P3 可选）；
2. 图表选 A（手写 SVG，推荐）还是 B（uPlot）；
3. 任务绑定是否按"单独恢复观察"方式回归；
4. Tier 2 端侧模型是否立项（建议先 Tier 1，真机数据出来再决策）。
